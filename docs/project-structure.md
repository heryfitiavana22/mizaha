## Important Rules

### 1. Providers — absolute rule

Never import a provider implementation directly in business logic.
Always go through the interface.

```typescript
// CORRECT
import type { SearchProvider } from "@/lib/providers/interfaces/search";

// FORBIDDEN — creates a direct dependency
import { BraveSearchProvider } from "@/lib/providers/search/brave";
```

### 2. Prompts — always in `ai/prompts/`

No LLM prompt is written inline in the code.
They are all in `src/lib/ai/prompts/` — versioned, modifiable independently from the code.

### 3. Pipeline — each step is independent

Each file in `pipeline/steps/` only knows its input and output.
It doesn't know what comes before or after it.
`pipeline/index.ts` is the only place that knows the order.

### 4. Use cases — only place that changes between cases

When adding the agency or the commercial use case, only touch `lib/use-cases/`.
The pipeline, providers, DB — nothing changes.

### 5. Drizzle schema — DB source of truth

`src/lib/db/schema.ts` is the database source of truth.
Never modify the DB manually — only through Drizzle migrations.

### 6. utils/ — not a dumping ground

Before adding something to `lib/utils/`, ask: is this truly a pure generic function,
or does it belong to a specific layer? Decide case by case while coding.
